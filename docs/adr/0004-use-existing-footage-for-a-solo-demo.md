# Use existing footage for a solo demo

Arranging filming participants is uncertain, so the hackathon demo will not depend on volunteers or cooperation from the panipuri stall. We will seek existing footage with verified permission for the intended public demo, showing a visible queue and service process compatible with the bounded model. The exact footage and service setting remain unselected; event check-in is no longer a required scene.

This replaces the staged filming requirement in ADR-0001 and the mandatory before-and-after physical experiment in ADR-0002. We can demonstrate calibration against observed behavior, but staffing changes must be presented as unvalidated model predictions unless suitable independent intervention evidence becomes available. Average waiting time remains the desired headline outcome, with queue length as supporting evidence; incomplete waits must remain explicit, and numerical outcomes must not imply measurements the footage cannot support.

No suitable footage has yet been verified. The seven-hours-per-day budget, model review step, and staffing-only what-if scope remain unchanged. The panipuri experience remains motivation rather than a filming dependency.

For the presentation, the selected clip may be analyzed beforehand and its actual results retained, while staffing what-ifs run live against the reviewed model. Fresh uploads remain supported, but the presentation does not depend on their processing latency. Saved analysis and live computation must be distinguished; saved results must originate from the actual analysis pipeline.

If a clip cannot support reliable waiting-time measurements, show the usable observations and request corrections or better footage rather than derive apparently measured waits from crowd counts alone. User-entered timings may support an exploratory simulation but remain labeled as assumptions.
